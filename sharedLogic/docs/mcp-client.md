# MCP HTTP client

Optional initial preloading has one aggregate 10-second work deadline, followed by bounded session cleanup. Servers not loaded before that deadline retain explicit discovery. Parent cancellation propagates independently.

`McpHttpSession` uses the official Kotlin MCP client SDK with Streamable HTTP. A session borrows the dedicated host-owned `createMcpHttpClient` transport. It checks literal destinations and each DNS answer, uses no proxy, follows no redirects and retries no failed connections. Private destinations require the operator's exact-URL `MCP_PRIVATE_ENDPOINT_ALLOWLIST`. Hosts with exceptions are restricted to those URLs, including scheme, port, path and query. Provider credentials and transports are independent. The caller closes the session; the HTTP client remains owned by the host.

Wire responses, including JSON success/error bodies and each SSE connection, have a 1 MiB byte cap before SDK buffering and a JSON nesting limit of 64. Only UTF-8 and identity encoding are accepted; Ktor receives a canonical UTF-8 content type. Tool discovery follows pagination and rejects duplicate names and repeated cursors. The execution admits at most 10,000 tools with a 4 MiB retained-metadata budget shared across servers; a listing has at most 100 pages. Names have at most 128 UTF-8 bytes and no controls, descriptions at most 2,000 characters and 4,000 JSON bytes, and each schema at most 16 KiB. A failed listing does not return a partial catalogue. MCP operation deadlines are capped at 60 seconds. Tool invocations are never automatically replayed by the adapter.

Tool results retain the SDK's content blocks, structured content, metadata and `isError`. A tool-level error is a returned result; a protocol or transport failure remains an exception.

`McpToolCatalog` belongs to one owner and execution. Discovery publishes an immutable catalogue only after a complete successful listing, and repeated loads reuse that execution's session. Skill IDs encode both server and tool identity without delimiter ambiguity. MCP-backed Skills expose SDK-provided schemas through `SkillToolSchemas` and execute through the ordinary `RunSkillCommand` path. Missing or mismatched owner identity cannot invoke the server. Adapter-owned timeouts become structured failures; parent coroutine cancellation propagates. Closing the catalogue closes its sessions without closing the borrowed HTTP client.

`LoadMcpTools` lists up to 20 summaries by default, accepts an `offset` and a `limit` from 1 to 50, and returns `totalTools` and `nextOffset`. Its result has a 16 KiB byte budget. Pagination reads cached summaries without repeating MCP discovery. Category names and details also accept `offset` and `limit`, default to 20, and return `totalSkills` and `nextOffset`; category detail pages have a 16 KiB budget and resolve one catalogue/index. Oversized category entries point to exact `GetSkillByName` lookup. Preload failures leave their servers discoverable for an explicit retry; cancellation propagates.

SDK `Client.close()` closes local transport resources. The adapter separately calls `StreamableHttpClientTransport.terminateSession()` before local closure, so session-bearing servers receive DELETE. Protocol notifications and DELETE use independent request/connect/socket deadlines of at most 500 ms, including the SDK's non-cancellable cancellation notification. Remote termination has a 500 ms bound and local close a one-second bound. Catalogue shutdown closes its at most 64 sessions concurrently; it releases the discovery mutex before network cleanup. Local close still runs when termination fails or stalls. Servers without session IDs require no termination request; HTTP 405 is accepted by the SDK. Cleanup runs independently of parent cancellation.

SDK 0.16.0 represents tool schema roots using `type`, `properties`, `required`, `$schema` and `$defs`. Other root keywords, including root `additionalProperties`, are not retained by its decoder. Nested property schemas remain JSON objects and preserve their keywords. Souz retains the SDK schema as JSON rather than narrowing it through its compiled-tool parameter DTO. The remote server remains responsible for argument validation. Full JSON Schema root fidelity requires an SDK change.
