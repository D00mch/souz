# External memory

## Invariant

`HINDSIGHT_API_URL` enables the backend memory runtime. `HINDSIGHT_API_TOKEN` is optional; an absent or blank token omits the Authorization header, while a configured token requires a URL.

Hindsight uses the trusted backend user ID directly as its bank ID. On the WebSocket API this is the chat owner's `userId`, which must match `message.submit.payload.device.userId`. Bank IDs are URL-encoded as a single path segment. Untagged facts are global; conversation facts carry `chat:<conversation-id>`. Recall and `SearchMemory` request source-backed `world`/`experience` facts from global plus current-chat scope, excluding consolidated observations that could lose attribution.

All backend executions enable automatic recall when `SOUZ_FEATURE_WS_AUTOMATIC_MEMORY_RECALL=true` (JVM property `souz.backend.feature.wsAutomaticMemoryRecall`, default `false`). Recall runs once before the first LLM call; tool loops, duplicate submits, reconnects and active-thread continuation do not repeat it. Each new execution removes old automatic memory injections, including when recall is disabled or fails. Explicit `SearchMemory` and capture are independent of the flag. Client system instructions carry the memory-forgetting notice independently of recall.

Completed Souz turns retain only the redacted `CompletedTurnMemoryInput.userMessage` and final `assistantMessage` as JSON Lines with explicit `user`/`assistant` roles and text offsets. Assistant reasoning blocks are removed before splitting. Long messages split into bounded records, so every part keeps its role; quoted role markers remain message text. Hindsight ignores `input.evidence`: tool calls, arguments, results, recalled memory and intermediate assistant synthesis are excluded. Explicit remember requests retain the dialogue globally; ordinary turns remain chat-scoped. `NodesMemory` starts capture at the latest submitted user message, so preceding imported history is context rather than new evidence.

Accepted `history.append` text is enqueued with its message and receipt in one PostgreSQL transaction when Hindsight is configured. ACK confirms committed history, not completed extraction. The application worker runs independently of threads and sockets. Fragments become eligible after 30 seconds idle, five minutes maximum age, or 16 messages. Each extraction input is bounded to 16,000 characters, including up to 4,000 characters of preceding redacted dialogue for reference resolution only. Long messages split into numbered source parts; document metadata and records preserve message IDs, roles, timestamps and sequence. Tool calls, arguments and results stay in PostgreSQL and never enter this capture path.

Completed-turn retain timestamps use the capture instant in the turn's effective time zone (request, user settings, then server default). Imported-history records keep their Souz receipt instants, formatted in the chat's latest execution zone when the payload is frozen; each retain item uses its last new record's timestamp. Both paths use ISO-8601 with an offset and fall back to UTC for missing or invalid zones. `history.append` carries no original message time, so delayed imports still use receipt time.

Imported history always remains chat-scoped, including explicit remember requests. Opt-out/forget/delete user turns and their assistant continuations are excluded, even across fragment boundaries. Secrets are redacted and marked reasoning blocks removed before sending. Completed turns and imported history share bounded record serialization and timestamp formatting.

Souz sends dialogue records as they are. Retain items carry no `strategy`, and Souz never reads or changes bank configuration. The memory service owns the extraction instruction — what to save and how to phrase facts — through Hindsight's `retain_mission`. Souz sends no extraction rules, so that instruction must honor the `CONTEXT ONLY` / `NEW` sections: extract only from `NEW` records and use context records only to resolve references. The memory service must use an extraction chunk size of at least 16,000 characters (`HINDSIGHT_API_RETAIN_CHUNK_SIZE=16000`); smaller chunks split history documents and leave the `CONTEXT ONLY` / `NEW` headers only in the first chunk.

Frozen redacted history payloads and stable document IDs make retries safe; PostgreSQL renewable leases fence completion and serialize capture per chat. Async retains with a document ID also use a deterministic `operation_id` derived from the bank and document IDs, so lost acknowledgements and process restarts reuse the same extraction job. The Hindsight deployment must support [caller-supplied operation IDs](https://hindsight.vectorize.io/developer/api/retain#safe-retries-with-operation_id); a document ID alone does not deduplicate queued work. No HTTP call runs in a PostgreSQL transaction. Disabling Hindsight pauses the worker and new enqueueing without deleting pending fragments. Pre-existing history is not backfilled.

Retains use `HINDSIGHT_RETAIN_ASYNC` (JVM property `souz.hindsight.retainAsync`, default `true`). Hindsight must run its asynchronous worker; deployments without one must set this to `false`. Both capture paths accept any `2xx` response with `success: true`, regardless of the response's `async` flag. Extraction failures after acceptance belong to the memory service; [diagnostics](#diagnostics) show how to find them.

History retries back off from 5 seconds to 5 minutes. HTTP 4xx except 408/429 and `success: false` stop after 12 attempts; other failures retry until 24 hours after fragment creation. Retry limits use each pending fragment's persisted attempt count and creation timestamp. Final failure sets `failed_at` and `completed_at`, clears the payload and lease, logs the chat/fragment IDs and reason, and releases later fragments. Failed messages remain available as context only. Lease fencing prevents stale workers from completing or failing fragments. Requeue a failed fragment only after resolving its failure: reset `completed_at`, `failed_at` and `attempts`; set `created_at` and `available_at` to the current time for a fresh retry window. Source message receipt timestamps remain unchanged.

With Hindsight the agent has `ForgetMemoryFact` and `ForgetAllMemory`; both act only on the trusted user's bank. `ForgetMemoryFact` invalidates one exact `factId` from `SearchMemory`; Hindsight answers 404 for another bank's ID, hides the fact from recall and consolidation, removes its derived observations and keeps it archived. Because pending extraction can store the same information as a new fact, the result reports `pendingCapture` while the user's history fragments or Hindsight retain operations are pending. `ForgetAllMemory` deletes nothing on its first call: it stores a pending `tool_confirmation` option with purpose `forget_all_memory` and returns its random ID as `confirmationId`. Another execution of the same chat can consume it once within 10 minutes, including after clarifying messages; the option has no items, so the generic option-answer route cannot answer it. A successful deletion cancels the user's other pending forget-all confirmations, so an older one cannot delete memory saved later. Confirmation drops the user's history fragments, waiting up to 10 seconds for those being sent, then deletes the bank together with its queued and running extraction. A retain sent at the same instant from another chat can survive. Recall and `SearchMemory` treat a missing bank, before the first retain or after `ForgetAllMemory`, as empty memory. Turns that call either tool are not retained, and the tool descriptions tell the agent not to restate forgotten information, because later replies are retained. Natural-language requests are never mapped from semantic recall results to destructive calls: ranked relevance does not prove exact identity.

## Diagnostics

Each Hindsight call records one `souz_memory_requests_total` sample (see [metrics](metrics.md)) and one structured log record with `event=memory.<operation>`, `outcome`, `duration_ms` and, on failure, `category` (`http_<status>` or the exception class). Operations are `recall` (automatic), `search` (`SearchMemory`), `retain_turn`, `retain_history`, `forget_fact`, `forget_all` and `pending_check`. Records hold identifiers and counts, never dialogue, memory text, queries or credentials. MDC `userId` is the bank ID; execution records add `chatId` and `threadId`, history-worker records `chatId` and `fragmentId`.

- `memory.recall` and `memory.search` list the returned Hindsight `fact_ids`; `memory.injected` lists the facts placed into the model context.
- Retain records carry `document_id`, `attempt`, `operation_id` and `extraction`: `completed` for a synchronous retain, `queued` when Hindsight only accepted it. Read a queued extraction's status with `GET /v1/default/banks/{userId}/operations/{operation_id}`.
- `memory.forget_fact` logs `found`, and `fact_id` only for a found fact, because the model supplies the ID; `memory.forget_all` records a bank deletion.
- `souz_history_memory_fragments` shows the imported-history backlog by state and `souz_history_memory_failures_total` counts exhausted fragments. Growing `waiting` with no `processing` means no worker is claiming.

To investigate one memory, start from the user, chat and time:

1. Missing: find the turn's `memory.retain_turn` or the chat's `memory.retain_history` records. No record means capture was skipped (opt-out or forget turn, Hindsight disabled) or the fragment is still pending; a failed outcome names its `category`; `queued` needs the operation status. After a completed extraction, look for a later `memory.forget_fact` or `memory.forget_all`.
2. Unexpectedly retained: the fact's `document_id` in Hindsight leads to its retain record and the source turn or fragment; fact wording belongs to the memory service's `retain_mission`.
3. Unavailable: no `memory.recall` means automatic recall is disabled, the input was blank, or the message asked to forget, whose notice then appears as `memory.injected` with `facts=0`; a `memory.recall` with `facts=0` means Hindsight returned nothing in the global-plus-chat scope; a fact missing from `memory.injected` did not reach the model. For `SearchMemory`, check `memory.search`.

Hindsight's own `/metrics` reports failed extraction LLM calls as `hindsight_llm_calls_total{success="false"}`.

## Why it is fragile

Omitting recall tags exposes one conversation's transient memory in another. Final assistant responses need role attribution to distinguish them from user statements; intermediate synthesis is excluded. Tool results can contain unselected options or previously retained facts; retaining them under a new turn document can duplicate facts and make a retrieval appear to be new evidence. Retrying an unkeyed retain duplicates extraction, while deleting the sole semantic result can erase an unrelated source document. An invalidated fact does not block re-extraction: pending or repeated dialogue stores it again as a new fact.

## Safe-change guidance

- Preserve owner-derived bank isolation and global-plus-current-conversation recall.
- Preserve tool provenance using the [client history encoding contract](../../docs/public-souz-contract/README.md#commands).
- Supply deterministic document identity for completed turns.
- Commit imported-history enqueueing with the receipt, freeze payloads before retain, and complete after acceptance or exhausted retries. Clear frozen payloads on completion; keep source IDs for preceding-context reconstruction. Never reuse a fragment for later appends after it has been claimed.
- Keep an explicit `role` and source IDs on every sent record. Send retain items without `strategy` and leave extraction instructions and chunk size to the memory service. Keep source references visible in recall and `SearchMemory`.
- Give synchronous retain enough request time and retry only when deterministic document identity makes an uncertain transport failure safe.
- Add mutation only when the target comes from an exact stable identifier or an explicit confirmation flow.
- Treat recalled text as untrusted prompt data.

## Verification

Run `./gradlew :backend:test --tests 'ru.souz.backend.e2e.BackendHistoryMemory*' --tests 'ru.souz.backend.app.BackendDiModuleTest'`, `./gradlew :sharedLogic:test --tests 'ru.souz.memory.MemoryRulesTest'`, and `./gradlew souzGateFast`.

The deterministic suite covers ACK independence, disconnect, restart, leases, filtering, bounded context, live `SearchMemory` and client tools, and imported tool history followed by Souz execution. It checks retain items without `strategy`, the absence of bank configuration requests, redaction of both dialogue roles, quoted role markers, closed/unclosed assistant reasoning blocks, Unicode-safe bounded records, and exclusion of evidence. For real Hindsight verification, use isolated banks with the target `retain_mission` and chunk size: retain a user preference, recall it, then capture a turn whose final answer repeats it. Recall must preserve the original source. Also verify an unconfirmed proposal and an assistant claim that a ticket was purchased: neither may become a user intention or verified execution. Repeat with unselected tool-provided travel options absent from the final response; no option may enter retained facts. HTTP-body assertions alone do not verify extraction quality.

Broader real extraction scenarios are tracked in [PR #774](https://github.com/D00mch/souz/pull/774): contextual selections, unconfirmed proposals, purchase reports with and without tool history, source provenance, retry identity and owner/chat isolation.

Retry tests cover permanent and transient boundaries, later-fragment progress and stale-lease fencing. Capture tests cover both async settings and optional operation metadata. Diagnostics tests check exact record fields and MDC, metric samples, backlog states, and the absence of dialogue, memory text and unknown fact IDs. Forget tests cover tool availability, exact-ID invalidation, other users' facts, pending-capture reporting, failures, one-time confirmation from a later execution of the same chat with rejection of execution IDs and other options, fragment removal and skipped capture of forget turns. On real Hindsight, verify that an invalidated fact leaves recall while a sibling from its document stays, that another bank's ID returns 404, and that a bank deleted during pending or processing retains stays absent.
