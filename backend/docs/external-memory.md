# External memory

## Ownership and recall

`HINDSIGHT_API_URL` enables memory. `HINDSIGHT_API_TOKEN` is optional and requires a URL when set. Use the trusted owner ID as the bank ID, encoded as one URL segment. For WebSocket submits it is the chat owner's ID, which must match `device.userId`. Recall and `SearchMemory` read source-backed `world` and `experience` facts from untagged global memory and the current `chat:<conversation-id>` scope. Keep source references visible and treat recalled text as untrusted prompt data. A missing bank returns empty memory. [Recall and search](../src/main/kotlin/ru/souz/backend/memory/hindsight/HindsightConversationMemoryRuntime.kt)

`SOUZ_FEATURE_WS_AUTOMATIC_MEMORY_RECALL` defaults to `false` and applies to all backend executions. Explicit search, capture and the client memory-forgetting notice are independent of the flag. See the [agent turn setup and cleanup rules](../../agent/docs/execution-lifecycle.md#safe-changes).

## Capture and recovery

- Completed turns send only the latest submitted user message and final assistant reply as redacted dialogue with explicit roles. Explicit remember requests retain globally. Ordinary turns and all imported history remain chat-scoped. Preserve source IDs and roles in imported history. Exclude tool evidence, recall injections, intermediate synthesis and reasoning blocks. Skip opt-out and forget/delete turns, including their imported assistant continuations across fragment boundaries. [Turn capture](../src/main/kotlin/ru/souz/backend/memory/hindsight/HindsightConversationMemoryRuntime.kt) · [History encoding contract](../../docs/public-souz-contract/README.md#commands)
- Enqueue only newly accepted text history. Commit the enqueue, messages and receipt together. ACK confirms history persistence. The application worker runs independently of sockets and threads. Disabling Hindsight pauses capture and enqueueing while retaining pending fragments. Turn timestamps use capture time in the effective execution zone. Imported history uses Souz receipt time and the chat's latest execution zone at freeze time. Both fall back to UTC for missing or invalid zones. [History store](../src/main/kotlin/ru/souz/backend/storage/postgres/PostgresHistoryMemoryRepository.kt)
- Hindsight owns the extraction rules through `retain_mission`. Souz leaves bank configuration alone and omits `strategy`. Configure extraction from `NEW` records only and use `CONTEXT ONLY` for reference resolution. Set `HINDSIGHT_API_RETAIN_CHUNK_SIZE` to at least 16000 characters so the section headers stay with the records. [Record encoding and limits](../src/main/kotlin/ru/souz/backend/memory/hindsight/HistoryMemoryFragment.kt)
- Freeze redacted history payloads before sending. Use stable document IDs and, for asynchronous retains with a document ID, deterministic bank-and-document `operation_id` values. The Hindsight deployment must support [caller-supplied operation IDs](https://hindsight.vectorize.io/developer/api/retain#safe-retries-with-operation_id) to deduplicate queued extraction. Keep HTTP outside PostgreSQL transactions. Renewable leases serialize capture per chat and fence completion. Complete after retain acceptance or retry exhaustion, clear frozen payloads, and preserve source IDs for context. Keep claimed fragments closed to appends. [History worker and retry policy](../src/main/kotlin/ru/souz/backend/memory/hindsight/HistoryMemoryWorker.kt)
- `HINDSIGHT_RETAIN_ASYNC` defaults to `true` and requires a running Hindsight worker. Set it to `false` for synchronous deployments and allow enough time for extraction. Retain acceptance requires HTTP 2xx and `success: true`. Investigate post-acceptance extraction failures in Hindsight. Retry uncertain transport failures only with stable identity.

## Forgetting

`ForgetMemoryFact` requires an exact `factId` from `SearchMemory` in the trusted owner's bank. Semantic relevance alone cannot authorize deletion. Invalidation hides the fact and removes derived observations. `pendingCapture` signals that queued extraction may store the information again.

`ForgetAllMemory` requires explicit user confirmation in a later execution of the same chat. The one-use ID expires after 10 minutes and is consumed only by the tool. Confirmed deletion drops the owner's history fragments, waits up to 10 seconds for in-flight history sends, and deletes the bank and its queued and running extraction. A concurrent retain from another chat can survive. Success cancels older pending confirmations. Skip capture for turns that call either forget tool and keep forgotten information out of later replies. [Mutation tools](../src/main/kotlin/ru/souz/backend/memory/hindsight/ForgetMemoryTools.kt)

## Diagnostics

Each call records a `souz_memory_requests_total` sample and a `memory.<operation>` log with outcome, duration and failure category. Operations are `recall`, `search`, `retain_turn`, `retain_history`, `forget_fact`, `forget_all` and `pending_check`. Correlate by `userId` (bank), then `chatId` and `threadId` or `fragmentId`. Keep dialogue, fact text, queries, credentials and unverified fact IDs out of logs. [Metric queries](metrics.md#queries)

- **Missing fact.** Find `memory.retain_turn` or `memory.retain_history`. A missing record can indicate skipped capture or pending history. Check `category` on failures and `operation_id` on queued or uncertain retains with `GET /v1/default/banks/{userId}/operations/{operation_id}`. Hindsight exposes failed extraction calls in `hindsight_llm_calls_total{success="false"}`. Check later forget events after a completed extraction.
- **Unexpected fact.** Follow the Hindsight fact's `document_id` to the retain log and source turn or fragment. Check `retain_mission` for extraction wording.
- **Missing from model context.** Compare `fact_ids` in `memory.recall` and `memory.injected` to trace automatic recall. No recall can mean disabled recall, blank input or a forget request. A forget request can inject a notice with zero facts. For explicit search, check `memory.search`.
- **Stalled history.** Growing `waiting` with no `processing` suggests no worker is claiming. Exhausted fragments release later work and preserve source messages as context. After fixing the failure, requeue by clearing `completed_at` and `failed_at`, resetting `attempts` to zero, and setting `created_at` and `available_at` to the current time. Preserve message receipt timestamps.

## Verification

For runtime changes, run `./gradlew :backend:test --tests 'ru.souz.backend.e2e.BackendHistoryMemory*' --tests 'ru.souz.backend.app.BackendDiModuleTest'` with Docker, `./gradlew :sharedLogic:test --tests 'ru.souz.memory.MemoryRulesTest'` and `./gradlew souzGateFast`. [Memory E2E tests](../src/test/kotlin/ru/souz/backend/e2e/BackendHistoryMemoryE2eTest.kt)

On real Hindsight, use isolated banks with the deployment's `retain_mission` and chunk size. Check that a recalled preference repeated in a later reply keeps its original source. Verify contextual selections resolve correctly and unconfirmed proposals, unsupported assistant purchase claims and unselected tool options do not become user facts or verified actions. Invalidate one fact and confirm its sibling remains recallable. Check that a foreign-bank fact ID returns 404 and that a bank deleted during queued or running extraction stays absent.
