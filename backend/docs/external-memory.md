# External memory

## Ownership and recall

`HINDSIGHT_API_URL` enables memory, with an optional `HINDSIGHT_API_TOKEN`. Use the trusted owner's ID as the bank ID. Recall and search read source-backed facts from untagged global memory and the current chat only. Keep source references visible and treat recalled text as untrusted prompt data. A missing bank returns empty memory. [Recall and search](../src/main/kotlin/ru/souz/backend/memory/hindsight/HindsightConversationMemoryRuntime.kt)

`SOUZ_FEATURE_WS_AUTOMATIC_MEMORY_RECALL` defaults to `false` and applies to all backend executions. Explicit search, capture and the client memory-forgetting notice are independent of the flag. See the [agent turn setup and cleanup rules](../../agent/docs/execution-lifecycle.md#safe-changes).

## Capture and recovery

- Completed turns send only the latest submitted user message and final assistant reply as redacted dialogue with explicit roles. Explicit remember requests retain globally. Ordinary turns and all imported history remain chat-scoped. Preserve source IDs and roles in imported history. Exclude tool evidence, recall injections, intermediate synthesis and reasoning blocks. Skip opt-out and forget/delete turns, including their imported assistant continuations across fragment boundaries. [Turn capture](../src/main/kotlin/ru/souz/backend/memory/hindsight/HindsightConversationMemoryRuntime.kt) · [History encoding contract](../../docs/public-souz-contract/README.md#commands)
- Enqueue only newly accepted text history, atomically with the messages and receipt. Run capture independently of sockets and threads. Disabling Hindsight preserves pending fragments and re-enabling it does not backfill history. Imported history uses Souz receipt time. [History store](../src/main/kotlin/ru/souz/backend/storage/postgres/PostgresHistoryMemoryRepository.kt)
- Hindsight owns the extraction rules through `retain_mission`. Souz leaves bank configuration alone and omits `strategy`. Configure extraction from `NEW` records only and use `CONTEXT ONLY` for reference resolution. Set `HINDSIGHT_API_RETAIN_CHUNK_SIZE` to at least 16000 characters so the section headers stay with the records. [Record encoding and limits](../src/main/kotlin/ru/souz/backend/memory/hindsight/HistoryMemoryFragment.kt)
- Use stable document IDs for both capture paths. Freeze redacted history before sending and keep claimed fragments closed to appends. Async deployments must support deterministic caller-supplied `operation_id` values to deduplicate extraction. Keep HTTP outside transactions and fence per-chat completion by lease. Clear frozen payloads after acceptance or retry exhaustion and retain source IDs for context. [History worker](../src/main/kotlin/ru/souz/backend/memory/hindsight/HistoryMemoryWorker.kt) · [Hindsight retry contract](https://hindsight.vectorize.io/developer/api/retain#safe-retries-with-operation_id)
- `HINDSIGHT_RETAIN_ASYNC` defaults to `true` and requires a running Hindsight worker. Set it to `false` for synchronous deployments and allow enough time for extraction. Retain acceptance requires HTTP 2xx and `success: true`. Investigate post-acceptance extraction failures in Hindsight. Retry uncertain transport failures only with stable identity.

## Forgetting

Expose forgetting tools only with Hindsight on authenticated interactive owner turns through the trusted proxy or linked Telegram/VK conversations. Persist this explicit authority for option continuations. Credential-free Client-Souz, hook and scheduled turns cannot delete memory; matching caller-supplied UUIDs and authenticated integrations do not grant owner deletion authority.

`ForgetMemoryFact` requires an exact `factId` from `SearchMemory` in the trusted owner's bank. Semantic relevance alone cannot authorize deletion. Invalidation hides the fact and removes derived observations. `pendingCapture` includes queued or in-flight completed-turn capture, imported history and Hindsight extraction that may store the information again.

`ForgetAllMemory` requires explicit user confirmation in a later execution of the same chat. The one-use ID expires after 10 minutes and is consumed only by the tool. Serialize each owner's completed-turn captures, including IO retries, ahead of bank deletion. Register capture before graph finalization returns and keep serialization and HTTP asynchronous. Confirmation waits up to 10 seconds for earlier captures and history sends, then drops queued history and deletes the bank with its queued and running extraction. If capture cannot drain, fail without deleting the bank or active fragments and require a new confirmation. Successful deletion discards captures registered while its owner barrier was held; failure preserves them, and later captures can retain new memory. A retain from another backend process can survive. Release idle owner coordination state atomically, including after cancellation and failure. Success cancels older pending confirmations. Skip capture for turns that call either forget tool and keep forgotten information out of later replies. [Mutation tools](../src/main/kotlin/ru/souz/backend/memory/hindsight/ForgetMemoryTools.kt)

## Diagnostics

Each call records a `souz_memory_requests_total` sample and a `memory.<operation>` log with outcome, duration and failure category. Operations are `recall`, `search`, `retain_turn`, `retain_history`, `forget_fact`, `forget_all` and `pending_check`. Correlate by `userId` (bank), then `chatId` and `threadId` or `fragmentId`. Keep dialogue, fact text, queries, credentials and unverified fact IDs out of logs. [Metric queries](metrics.md#queries)

- **Missing fact.** Find `memory.retain_turn` or `memory.retain_history`. A missing record can indicate skipped capture, pending work or capture discarded by successful owner deletion. Check `category` on failures and `operation_id` on queued or uncertain retains with `GET /v1/default/banks/{userId}/operations/{operation_id}`. Hindsight exposes failed extraction calls in `hindsight_llm_calls_total{success="false"}`. Check later forget events after a completed extraction.
- **Unexpected fact.** Follow the Hindsight fact's `document_id` to the retain log and source turn or fragment. Check `retain_mission` for extraction wording.
- **Missing from model context.** Compare `fact_ids` in `memory.recall` and `memory.injected` to trace automatic recall. No recall can mean disabled recall, blank input or a forget request. A forget request can inject a notice with zero facts. For explicit search, check `memory.search`.
- **Stalled history.** Growing `waiting` with no `processing` suggests no worker is claiming. Exhausted fragments release later work and preserve source messages as context. After fixing the failure, requeue by clearing `completed_at` and `failed_at`, resetting `attempts` to zero, and setting `created_at` and `available_at` to the current time. Preserve message receipt timestamps.

## Verification

For runtime changes, run `./gradlew :backend:test --tests 'ru.souz.backend.e2e.BackendHistoryMemory*' --tests 'ru.souz.backend.app.BackendDiModuleTest'` with Docker, `./gradlew :sharedLogic:jvmTest --tests 'ru.souz.memory.MemoryRulesTest'` and `./gradlew souzGateFast`. [Memory E2E tests](../src/test/kotlin/ru/souz/backend/e2e/BackendHistoryMemoryE2eTest.kt)

Cover rejected forgetting calls from credential-free, hook and scheduled turns, continuation authority, capture/retry draining, timeout without deletion, independent owners and deletion fencing on success only.

On real Hindsight, use isolated banks with the deployment's `retain_mission` and chunk size. Check that a recalled preference repeated in a later reply keeps its original source. Verify contextual selections resolve correctly and unconfirmed proposals, unsupported assistant purchase claims and unselected tool options do not become user facts or verified actions. Invalidate one fact and confirm its sibling remains recallable. Check that a foreign-bank fact ID returns 404 and that a bank deleted during queued or running extraction stays absent.
