# Metrics accounting

Repository commits own execution outcomes and history-fragment failures. Observe successful active-to-terminal writes and failed fragment completions inside the JDBC dispatcher after commit; observing service responses can double-count idempotent retries or lose cancellation finalization. Runtime state and durable replay remain independent of meters.

One shared registry holds backend execution metrics, JVM binders, pool instrumentation, and job-owned queue metrics. Compose `PostgresJobService.bindMetrics` with that registry; queue SQL stays in `:job-impl`. Gauge evaluation performs JDBC IO, so scrape on `Dispatchers.IO`. Configure Hikari's tracker before constructing its datasource, and close meters after application work and storage. Active execution, history-fragment and oldest-due-job gauges read shared PostgreSQL state; aggregate replicas with `max`. Other counters and work gauges belong to one instance.

Keep elapsed timing monotonic and process-local. Scheduled dispatch delay and queue age instead compare calendar timestamps as described in the [metric reference](metrics.md). Exclude the union of client-result waits and option waits from processing, retaining a separate option clock through concurrent client waits. Preserve stream usage high-water marks across empty/repeated/decreasing snapshots. Finish tool accounting in `finally`. Wrap compiled catalog tools before Skill helpers can convert failures into result messages; exclude catalog tools from kernel telemetry to avoid counting direct subagent calls twice. Typed client outcomes belong to their transport.

Keep channel eviction atomic through `DROP_OLDEST` and its undelivered callback. Count command queue rejection directly from failed `trySend`; it does not invoke the undelivered callback. Losses belong to each subscriber even if another accepts the command. Only actual public live events count as losses; replay/control events and bot observers do not. Bound model, route, category and exception labels as described in the [metric reference](metrics.md).

Verify with `./gradlew :backend:test :agent:test souzGateFast` and `./gradlew souzDuplicationCheck`. Existing execution, option, provider, client-tool and event-bus tests cover accounting at their normal boundaries; `BackendMetricsE2eTest` checks the production scrape and shared load.
