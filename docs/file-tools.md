# File Tool Conventions

File tools resolve paths in the invocation's sandbox. Use `~`, `$HOME`, or `home` for its home directory. [Path resolution and Souz documents directory](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/runtime/files/FilesToolUtil.kt)

LOCAL checks effective paths against its canonical home root and user-forbidden folders. A workspace at `~/project` still permits access to `~/Documents` unless explicitly forbidden. DOCKER checks effective paths against its mounted sandbox root and configured forbidden paths. [LOCAL boundary](../sharedLogic/src/jvmMain/kotlin/ru/souz/runtime/sandbox/local/LocalSandboxFileSystem.kt) · [DOCKER boundary](../sharedLogic/src/jvmMain/kotlin/ru/souz/runtime/sandbox/docker/DockerSandboxFileSystem.kt) · [Sandbox rules](../sharedLogic/docs/runtime-sandbox-and-skills.md)

The attachment path normalizer trims whitespace, unwraps simple quotes, strips `file://`, and expands `~`. It returns a canonical absolute path for an existing regular file and `null` otherwise. [Normalization](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/runtime/files/FilesToolUtil.kt)

## Tool Guarantees

- `ListFiles` walks a safe existing directory and returns a bracketed string of absolute child paths, with `/` after directories. LOCAL skips forbidden paths and dot-prefixed directories. DOCKER hides all dot-prefixed entries and rejects unsafe non-symlink descendants. Listings over 25,000 characters return an error. [Tool and example](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolListFiles.kt) · [LOCAL](../sharedLogic/src/jvmMain/kotlin/ru/souz/runtime/sandbox/local/LocalSandboxFileSystem.kt) · [DOCKER](../sharedLogic/src/jvmMain/kotlin/ru/souz/runtime/sandbox/docker/DockerSandboxFileSystem.kt)
- `NewFile` creates a text file and any missing parent directories. A trailing slash creates a directory. Existing paths are rejected. [Tool and examples](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolNewFile.kt)
- `EditFile` replaces exact text in an existing UTF-8 text, code, or config file. Empty or missing search text and no-op replacements fail. Multiple matches require `replaceAll`. Matching normalizes line endings and preserves untouched text. Validate before requesting permission. Desktop safe mode stages edits against a virtual file state for review after tool use; users may apply or discard individual edits. Replay selected edits in order, reporting conflicts when an earlier discarded edit breaks a later one. Reread touched files before applying and skip files changed externally. Outside safe mode, write after validation. The backend catalogue controls backend availability. [Tool and example](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolModifyFile.kt) · [Replacement rules](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolModifyFilePlanner.kt)
- `MoveFile` moves a regular file to a distinct, unused path and creates missing destination parents. [Tool and example](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolMoveFile.kt)
- `DeleteFile` prefers the desktop Trash API when available and otherwise uses sandbox Trash locations, adding a timestamp suffix on fallback name collisions. [Tool and example](../sharedLogic/src/commonJvmMain/kotlin/ru/souz/tool/files/ToolDeleteFile.kt) · [LOCAL Trash locations](../sharedLogic/src/jvmMain/kotlin/ru/souz/runtime/sandbox/local/LocalSandboxFileSystem.kt)
- `CreatePlot` writes a PNG from CSV, XLS, or XLSX. The backend accepts `openAfterCreate` for compatibility and leaves opening the file to the caller. [Tool and examples](../sharedLogic/src/jvmMain/kotlin/ru/souz/tool/dataAnalytics/ToolCreatePlotFromCsv.kt)
