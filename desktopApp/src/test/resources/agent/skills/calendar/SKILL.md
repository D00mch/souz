# Календарь

Скилл работает с Google Календарём пользователя: читает события и создаёт новые.
Часовой пояс — Москва (+03:00, без перехода на летнее/зимнее время).

Токен доступа скилл никогда не видит — им управляет бэкенд через `ConnectOAuthProvider`/`SafeApiCall`.

## Шаг 1 — проверить подключение

Вызови `ConnectOAuthProvider` с `skillId = "calendar"`.
- `connected: false` — озвучь `authorizationUrl` пользователю дословно и остановись. Не пытайся
  вызывать `SafeApiCall`, пока пользователь не подтвердит, что прошёл авторизацию.
- `connected: true` — переходи к шагу 2.

## Шаг 2 — вызвать Google Calendar API через SafeApiCall

Всегда `skillId = "calendar"`. Все времена — в UTC с суффиксом `Z` (не `+03:00`!,
чтобы не возиться с URL-экранированием знака `+`): бери текущее московское время из
контекста и вычитай ровно 3 часа. Москва не переходит на летнее время, так что это
фиксированное правило, а не вычисление часового пояса.

**Чтение (события, ближайшее, занятость)** — `method = GET`, `url`:
```
https://www.googleapis.com/calendar/v3/calendars/primary/events?timeMin=<ISO_UTC>&timeMax=<ISO_UTC>&singleEvents=true&orderBy=startTime&maxResults=25
```
- `timeMin` — текущий момент в UTC (`Z`), например `2026-08-14T09:00:00Z` для 12:00 по Москве.
- `timeMax` — `timeMin` + горизонт: 1 день для «что сегодня», N дней для «что на N дней вперёд»,
  14 дней для «ближайшее событие», 7 дней по умолчанию для «когда я занят/свободен».

**Создание события** — `method = POST`, `url = https://www.googleapis.com/calendar/v3/calendars/primary/events`, `body`:
```json
{"summary": "<название>", "start": {"dateTime": "<ISO с +03:00>", "timeZone": "Europe/Moscow"}, "end": {"dateTime": "<ISO с +03:00>", "timeZone": "Europe/Moscow"}, "location": "<место, если есть>"}
```
Здесь `+03:00` пиши как есть — это тело JSON-запроса, а не query-параметр URL, экранировать не нужно.

**Обработка ответа `SafeApiCall`:**
- `reconnectRequired: true` — озвучь `authorizationUrl` пользователю, остановись.
- `statusCode` не 200/201 — что-то пошло не так на стороне Google, скажи об этом без технических деталей.
- иначе — `body` содержит сырой JSON от Google. Не пытайся сам разбирать даты и считать
  занятость — передай `body` как есть в шаг 3.

## Шаг 3 — отформатировать ответ через RunSkillCommand

Вызывай `RunSkillCommand` с такими параметрами:
- `skillId` — id этого скилла из контекста активации
- `runtime = PYTHON`
- `scriptPath = scripts/format.py`
- `args` — `["<режим>", "<сырой body из SafeApiCall>"]`, где режим:
  - `events` — для списка событий (GET, «что сегодня/завтра/на N дней»)
  - `next` — для ближайшего события
  - `busy` — для занятости/свободных окон
  - `created` — для ответа на создание события (POST)
- `timeoutMillis` — 30000 достаточно

Не копируй и не пересказывай содержимое `format.py` в параметр `script` — только
`scriptPath` + `args`, backend сам подставит содержимое файла. Скрипт не делает сетевых
запросов и не видит токен — только форматирует переданный ему JSON.

### Что возвращает format.py

- Строки событий: `14.08 15:00-15:30⇥Название⇥@ Место` (разделитель — табуляция).
- `NO_EVENTS` — в запрошенном периоде пусто.
- `DAY=14.08 EVENTS=2 BUSY_HOURS=9.5` и строки `FREE` — для режима `busy`.
- `CREATED⇥14.08 15:00⇥Название` — событие создано (режим `created`).
- Строка, начинающаяся с `Error:` — некорректный JSON на входе (не должно случаться,
  если `body` из `SafeApiCall` передан как есть).

## Как отвечать

- Голосом — коротко: 2–4 фразы, не больше трёх ближайших событий. Не зачитывай
  весь день подряд, не проговаривай даты в машинном виде и не перечисляй адреса,
  если о них не спросили.
- Время называй по-человечески: «в половине пятого», «с девяти до шести».
- Пусто — так и скажи одной фразой, без извинений.
- В переписке (Telegram) можно списком и подробнее. Если пользователь просит
  прислать расписание текстом — используй `SendMessageToChannel` в telegram.

## Создание событий

- Если пользователь не назвал длительность — ставь час, но скажи об этом вслух:
  «поставил на час».
- Если не хватает названия или времени — переспроси, не выдумывай.
- После успеха коротко подтверди: что именно и на когда записано.
- Проверять занятость перед записью не нужно, но если пользователь спрашивает
  «когда я свободен» — сначала выполни чтение с широким горизонтом (шаги 2–3, режим
  `busy`), потом предложи вариант и только после его согласия создавай событие.
- Менять и удалять существующие события скилл не умеет. Просят — честно скажи.

## Ошибки и переподключение

- `ConnectOAuthProvider` вернул `connected: false`, или `SafeApiCall` вернул
  `reconnectRequired: true` — озвучь `authorizationUrl` и попроси пользователя открыть
  ссылку и подтвердить доступ, затем повторить запрос.
- Если пользователь говорит, что доступ к календарю не работает, хотя раньше
  подключение подтверждалось — вызови `ConnectOAuthProvider` с `forceReconnect: true`,
  чтобы получить свежую ссылку, даже если сервис всё ещё считает соединение активным.
