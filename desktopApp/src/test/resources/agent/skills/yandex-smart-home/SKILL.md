oauthProvider: yandex
oauthScopes:
  - iot:view
  - iot:control

  get_state:
    inputs: [mode, name]
    steps:
      - id: user_info
        tool: SafeApiCall
        arguments:
          skillId: yandex-smart-home
          method: GET
          url: https://api.iot.yandex.net/v1.0/user/info
      - id: parsed
        script: scripts/ysh_api.py
        runtime: PYTHON
        args: ["${inputs.mode}", "${user_info.body}", "${inputs.name}"]
    returns: "${parsed}"
  control_device:
    inputs: [device_id, state]
    steps:
      - id: action_body
        script: scripts/ysh_api.py
        runtime: PYTHON

        tool: SafeApiCall
        arguments:
          skillId: yandex-smart-home
          method: POST
          url: https://api.iot.yandex.net/v1.0/devices/actions
          body: "${action_body}"
      - id: confirmed
        script: scripts/ysh_api.py
        runtime: PYTHON
        args: ["check-action-result", "${sent.body}", "${inputs.device_id}"]
    returns: "${confirmed}"

# Yandex Smart Home

Управляй умным домом Яндекса через два готовых composite-вызова — каждый детерминированно
выполняет несколько шагов (вызов `SafeApiCall` + локальную обработку JSON) одним твоим ходом,
без отдельных решений на каждый шаг:

- **`get_state`** — `RunSkillCommand(skillId: "yandex-smart-home", arguments: {composite: "get_state", inputs: {mode, name}})`.
  `mode` — один из `rooms` / `devices` / `devices-compact` / `resolve-device-id`; `name` нужен
  только для `resolve-device-id`, иначе передай пустую строку `""`. Получает `user/info` и сразу
  разбирает его — см. таблицу ниже, что возвращает каждый `mode`.
- **`control_device`** — `RunSkillCommand(skillId: "yandex-smart-home", arguments: {composite: "control_device", inputs: {device_id, state}})`.
  `state` — `on`/`off` (также понимает `1`/`0`/`true`/`false`/по-русски). Строит тело команды,
  отправляет её и сразу проверяет результат (`DONE` или ошибка) — одним вызовом вместо трёх.

Оба возвращают уже готовый к использованию результат — сырой `SafeApiCall` дёргать напрямую для
обычных операций не нужно.

## Если аккаунт ещё не подключён

`SafeApiCall` (в том числе внутри `get_state`/`control_device`) не бросает ошибку, если OAuth не
подключён — он возвращает нормальный ответ с `reconnectRequired: true`. Оба composite-вызова это
пробрасывают как есть, так что ты увидишь тот же `reconnectRequired`/`authorizationUrl` в
результате `get_state`/`control_device`, как если бы вызвал `SafeApiCall` напрямую:

1. Если в ответе `reconnectRequired: true`:
   - Если есть уверенность, что пользователь сейчас видит текст (переписка,
     экран) — покажи `authorizationUrl` как есть (это ссылка, которую нужно
     открыть в браузере и подтвердить доступ), и попроси повторить исходную
     команду после подтверждения.
   - Если разговор идёт только голосом, без экрана (или нет уверенности,
     что пользователь видит текст) — **не проговаривай `authorizationUrl`
     вслух**. Вместо этого скажи, что для первого подключения аккаунта
     Яндекса нужно написать боту в Telegram или открыть приложение souz —
     по голосовой команде это не делается, потому что нужен браузер.
2. Если хочешь проверить статус подключения отдельно (не как часть обычной команды) — можно
   вызвать `ConnectOAuthProvider` с `skillId` этого скилла напрямую.

## Как читать состояние дома

| Что нужно | `mode` | `name` |
|---|---|---|
| Список комнат | `rooms` | `""` |
| Список устройств (id, имя, тип, room=id комнаты) | `devices` | `""` |
| Компактный список: комната, имя, id, on/off | `devices-compact` | `""` |
| id устройства по точному имени | `resolve-device-id` | искомое имя |

Состояние ОДНОГО устройства по известному id можно получить без composite —
`SafeApiCall(method: "GET", path: "https://api.iot.yandex.net/v1.0/devices/<device_id>")`,
используй `body` из ответа напрямую.

## Как управлять устройством по известному id

Один вызов: `control_device` с `inputs: {device_id, state}` (см. выше). Результат — тело ответа
`/v1.0/devices/actions` после проверки статуса; если что-то не `DONE`, в ответе будет `ERROR: ...`
— передай суть пользователю, не изобретай причину сам.

## Как управлять устройством по имени

0. Если `device_id` этого устройства (по тому же имени и той же комнате)
   уже встречался в этом разговоре раньше — не запрашивай состояние
   заново, используй уже известный id и сразу переходи к `control_device`.
   Свежий запрос состояния нужен, только если id ещё не известен,
   устройство не нашлось под известным id, либо пользователь прямо просит
   проверить текущее состояние.
1. Иначе вызови `get_state` с `mode: "resolve-device-id"` и `name` — искомым именем.
2. Дальше — `control_device` с найденным id.

## Если устройство не нашлось по имени

Названия устройств в Яндекс-доме часто общие ("Свет", "Розетка"), а привязка
к месту — это отдельное поле `room`, а не часть имени. Пользователь может
сказать "свет на третьем этаже" или "свет в спальне", хотя устройство
называется просто "Свет" и стоит в комнате "Третий этаж"/"Спальня".
`resolve-device-id` такие фразы не сопоставит — это сопоставление делай сам:

1. Вызови `get_state` с `mode: "devices-compact"` — один вызов сразу даёт и комнату, и имя, и id,
   и текущее состояние.
2. Сопоставь то, что сказал пользователь, с парой (имя устройства + имя его
   комнаты) — не только с голым именем устройства. "Свет на третьем этаже"
   и устройство "Свет" в комнате "Третий этаж" — это одно и то же.
3. Когда нашёл нужный `device_id` — управляй им напрямую по id (раздел выше),
   не через `resolve-device-id`.
4. Уточняй у пользователя, только если по смыслу подходит несколько
   устройств сразу или ни одно не подходит вообще — не переспрашивай,
   если сопоставление очевидно из контекста (комната + тип устройства).

## Ошибки

- `reconnectRequired: true` в результате — см. раздел "Если аккаунт ещё не подключён" выше.
- `401`/`403` от `api.iot.yandex.net` при уже подключённом аккаунте —
  токен на стороне Яндекса мог быть отозван; предложи пользователю
  переподключить аккаунт через `ConnectOAuthProvider`.
- Устройство не найдено по имени — см. раздел про сопоставление по
  комнате через `devices-compact`; переспрашивай пользователя, только
  если и так не получилось однозначно определить устройство.
