# Методы Python-скрипта

Один JSON-объект в stdin; неизвестные поля и неверные типы отклоняются. Ни один метод
не принимает пользователя, путь хранилища или токены. Код 0: сформирован предметный
результат, включая ошибку. Код 2: некорректный вызов/JSON; код 1: ошибка исполнения.

| Метод | Аргументы | Результат `data` |
|---|---|---|
| `get_auth_status` | `{}` | `state`, маска телефона, `account_number`, `auth_session_id`, сроки, `capabilities.scheduler=false` |
| `start_phone_auth` | `phone`, `request_id` | ID попытки, маска телефона, `delivery_status: requested/unknown`, сроки и локальные попытки |
| `submit_sms_code` | `auth_session_id`, `code` (строка), `request_id` | Статус входа |
| `resend_sms_code` | `auth_session_id`, `request_id` | `UNSUPPORTED_OPERATION`, без отправки SMS |
| `cancel_phone_auth` | `auth_session_id` | `cancelled`; отменяет только совпадающую текущую попытку |
| `logout` | `{}` | Статус без авторизации; удаляет токены и незавершённый вход |
| `search_products` | `query` | `products: [{id, name}]`, доступные сегодня по данным поиска |
| `get_product_analogs` | `product_id` | `products: [{id, name}]`, наличие не гарантировано |
| `get_completed_orders` | `limit` (необязательно, 1–20, по умолчанию 20) | `orders: [{id_order, supplied_at}]`, `requested_limit`, `pagination_supported=false` |
| `get_order_details` | `id_order` из списка заказов | `id_order`, `supplied_at`, `purchases: [{id, name, quantity, measure, category:null}]` |
| `get_cart` | `{}` | `cart_id`, `products: [{id, name, quantity, in_stock}]`, `fetched_at` |
| `add_to_cart` | `product_ids` (1–100 уникальных положительных целых), `request_id`, необязательный `substitution_policy:"none"` | Результат изменения |
| `remove_from_cart` | `product_ids`, `request_id` | Результат удаления позиций целиком; оставшиеся позиции отмечены как пропуски |
| `clear_cart` | `request_id` | Результат очистки |

`id_order` и `request_id` — непустые строки. Телефон: российские 10 цифр, +7 или 8;
допустимы пробелы, скобки и дефисы. SMS-код — строка цифр с ведущими нулями.
Авторизация требуется для всех товарных методов, включая историю и аналоги.
Значение `quantity` возвращается как у API, без предположения об единице корзины.

Успех: `{"ok":true,"data":...,"warnings":[]}`.
Ошибка: `{"ok":false,"error":{"code":...,"message":...,"retryable":false,
"retry_after_seconds":null,"operation_id":null,"details":{}}}`.

Результат изменения: `operation_id`, `outcome: applied/partial/unknown`, актуальная
`cart` или null, `applied_product_ids`, `skipped: [{product_id,reason}]`, `substitutions`.
Замены выбирает агент отдельными вызовами, поэтому `substitutions` скрипта пуст.
При неизвестном исходе результат находится в `error.details.mutation`, исходный
снимок — в `error.details.cart_before`. Перечитывание после сетевого сбоя не доказывает,
что изменения сделал именно этот запрос: пользователь может редактировать корзину
в приложении одновременно. Скрипт консервативно сохраняет `unknown`.

## Ошибки и продолжение

- `AUTH_REQUIRED`, `AUTH_EXPIRED`: нужен вход или восстановление. `ACCESS_DENIED`
  не означает автоматически истёкшую авторизацию или запрет аккаунта. При HTTP 403
  `details.stage` указывает шаг, `response_format` отличает JSON от другого ответа.
  `guest_session_create` означает отказ до отправки телефона и SMS: вход в приложении
  не является доказанным решением, передай диагностику оператору. Не повторяй автоматически.
- `AUTH_SESSION_EXPIRED`: начни новый вход по запросу пользователя. `ALREADY_AUTHENTICATED`:
  используй действующую сессию либо согласованный выход.
- `RATE_LIMITED`, `BUSY`: учитывай `retry_after_seconds`. `BUSY` означает, что другой
  процесс держит блокировку; текущий вызов ещё не отправлял запрос.
- `UPSTREAM_UNAVAILABLE`: исчерпаны безопасные GET-повторы. Пустой результат — отдельный успех.
- `UPSTREAM_PROTOCOL_ERROR`: непроверенная форма ответа, а не обязательно неверный SMS-код.
  Для входа с неизвестным исходом тот же `request_id` не отправляет запрос ещё раз.
- `OPERATION_OUTCOME_UNKNOWN`: никаких слепых повторов POST. Для входа может понадобиться
  новая попытка; для refresh — явный выход и новый вход. Для корзины перечитай состояние.
- `REQUEST_ID_CONFLICT`: ID уже относится к другим параметрам или другой сессии аккаунта.
  Не меняй ID ради обхода неизвестного результата.
- `REQUEST_ID_EXPIRED`: подробный результат хранится 24 часа; старый ID остаётся
  заблокирован для воспроизведения. Неизвестные операции сохраняются без TTL.
- `PRODUCT_NOT_FOUND`, `ORDER_NOT_FOUND`: используй данные текущего аккаунта из
  поддерживаемого поиска/истории. Произвольные ID не разрешают доступ к прошлому аккаунту.
- `CART_CONTEXT_REQUIRED`: настрой корзину/доставку в приложении ВкусВилла.
- `UNSUPPORTED_QUANTITY`, `UNSUPPORTED_OPERATION`: объясни конкретное ограничение.
- `STORAGE_UNAVAILABLE`, `INTERNAL_ERROR`: не объявляй успех; изменение могло уже уйти
  во ВкусВилл. После восстановления проверь прежний ID и состояние корзины.

## Локальные ограничения

Попытка входа живёт 10 минут, допускает 5 проверок кода. Начало входа ограничено
интервалом 60 секунд и тремя попытками за 15 минут на пользователя; отмена и выход
не сбрасывают лимит. Это локальные ограничения, не сроки и квоты ВкусВилла.
Непроверенные формы SMS-ошибок не классифицируются как неправильный/истёкший код.
Access token обновляется за 300 секунд до известного JWT `exp` или после GET 401.
JWT здесь лишь подсказка срока, а не доказательство прав. POST не повторяются.

Состояние и журнал общие для чатов пользователя, операции сериализованы между
процессами. История известных товаров и заказов разделена по аккаунту. Выход
удаляет секреты, но сохраняет эту историю и журнал. Не выдавай выход за удаление всех данных.
