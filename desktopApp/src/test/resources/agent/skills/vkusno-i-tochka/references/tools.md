# Методы скрипта

В argv передаётся только имя метода, в stdin — один JSON-объект. Неизвестные поля,
повторяющиеся JSON-ключи, неверные типы, NaN/Infinity и вход свыше 64 KiB отклоняются.
Ни один метод не принимает userId, токены, URL, путь состояния или HTTP-заголовки.

| Метод | Аргументы | Результат `data` |
|---|---|---|
| `get_auth_status` | `{}` | `state`, маска телефона, активный `auth_session_id`, локальный срок и capabilities |
| `start_phone_auth` | `phone`, `request_id` | `pending_sms`, ID попытки, `delivery_status`, локальные сроки и число попыток |
| `submit_sms_code` | `auth_session_id`, `code` строкой, `request_id` | Статус входа |
| `cancel_phone_auth` | `auth_session_id` | Отмена только указанной локальной попытки |
| `logout` | `{}` | Статус после удаления локальной авторизации |
| `search_restaurants` | `query`; необязательно `city`, `pickup`, `limit` | `restaurants`, `total_matches`, время чтения |
| `get_restaurant` | `restaurant_id` | Адрес, город, регион, геокоординаты, мобильные способы получения, часы на текущую дату ресторана |
| `select_restaurant` | `restaurant_id`, `pickup`, `request_id` | Черновик с выбранным рестораном; прежние товары сохраняются, цена сбрасывается |
| `search_products` | `query`; необязательно `limit` | Подходящие продукты меню выбранного ресторана |
| `get_product` | `product_id` | Название, размер, состав, аллергены, пищевая ценность, предварительная цена и доступность |
| `get_cart` | `{}` | Локальный черновик с последним расчётом, если он есть |
| `set_cart_items` | `items: [{product_id, quantity}]`, `request_id` | Итоговые количества перечисленных позиций; прочие сохраняются |
| `clear_cart` | `request_id` | Пустой локальный черновик |
| `calculate_cart` | `{}` | Черновик и серверный `quote`, свежие данные ресторана |
| `prepare_checkout` | `email`; для парковки `parking_zone`, `vehicle_plate`, `vehicle_color` | Свежие состав/сумма/ресторан, `checkout_id`, `expires_at`; без создания заказа |
| `create_order` | `checkout_id`, `request_id` | ID заказа, платёжная HTTPS-ссылка, фактическая сумма и начальный статус |
| `get_order_status` | `{}` либо `order_id` | Свежий статус последнего известного или указанного заказа |

Телефон: российские 10 цифр, +7 или 8; пробелы, скобки и дефисы допустимы.
Код: строка из 1–16 цифр. ID ресторанов и продуктов — положительные целые числа
из ответов соответствующего поиска, не MongoDB ID каталога. `limit`: 1–30,
по умолчанию 10. Query содержит буквы или цифры. `city` — точное название города.

`pickup`: `auto`, `takeaway`, `eat_in`, `parking`, `table`, `night_window`, `locker`.
Способ должен присутствовать в `mobile_pickups`. Оформление поддерживает четыре
основных варианта ниже; остальные доступны только для черновика/расчёта:

| Получение | `pickup` | `wayOfGet` |
|---|---|---|
| Авто | `auto` | 3 |
| На парковке | `parking` | 2 |
| На прилавке с собой | `takeaway` | 4 |
| На прилавке на подносе | `eat_in` | 5 |

Ресторан возвращает `parking_zone_range: {min,max}` либо null: это включительный
диапазон зон из каталога, не список свободных мест. Он сам по себе не подтверждает
доступность парковочной выдачи — проверяйте `mobile_pickups`. Для расчёта номер зоны,
номер и цвет машины не требуются. Они передаются в `prepare_checkout` для парковки.
Смена способа через `select_restaurant` сохраняет товары и сбрасывает прежний расчёт.

В `items` допустимы 1–50 уникальных ID; quantity — целое 0–20, 0 удаляет позицию.
Суммарно не более 100 единиц. Изменение атомарно: неизвестная/недоступная позиция
не приводит к частичному сохранению остальных. Стандартный состав используется
без добавок и исключения ингредиентов. В расчёт и создание включаются стандартные
группы выбора, включая нулевой служебный вариант у фри; они не добавляют платный соус.
Автоматическая упаковка исходных отдельных продуктов в пары/комбо использует точный
выбор компонентов из меню. Вложенные/неподдержанные группы пропускаются;
прямая передача ID комбо без выбора компонентов не поддерживается.
Скрипт выбирает первый доступный вариант по сортировке каталога, только если он
включён в цену и доступен во всех периодах основного продукта. Обычные ингредиенты
RAW_ITEM подразумеваются, как в Android; произвольный выбор не реализован.

## Результаты

Успех: `{"ok":true,"data":...,"warnings":[]}`.
Ошибка: `{"ok":false,"error":{"code":...,"message":...,"retryable":false,
"retry_after_seconds":null,"operation_id":null,"details":{}}}`.
Exit code 0 означает предметный результат, включая `ok=false`; 2 — неверный JSON,
1 — ошибка исполнения/хранилища.

Черновик: `kind: "souz_draft"`, `visible_in_provider_app:false`, ресторан,
`items: [{product_id,name,quantity,product_class}]`, `revision` и `quote` либо null.
Выбор ресторана и изменения состава сбрасывают quote. Перед расчётом прежний quote
также сбрасывается: ошибка не оставляет старую сумму как актуальную.

Quote содержит `confirmed`, `total`, `currency:"RUB"`, позиции с `unit_price`,
серверным количеством и `accepted`, `unavailable_product_ids`, `quoted_at`,
`cart_revision`. `confirmed=true` требует, чтобы сервер вернул все запрошенные
позиции с нужным количеством, ценами и без ошибок/отсутствия. Цена предварительного
метода не используется для итогового сложения и не передаётся как желаемая цена.
Персональные предложения, награды и списание бонусов не применяются.

## Выгодная упаковка и товарные акции

`calculate_cart` сохраняет запрошенные товары в `items`, но сравнивает их обычную
цену с совместимыми парами, сетами, комбо и обычными товарными предложениями аккаунта.
Сохраняются количество, вкусы и размеры; никаких дополнительных блюд или бесплатных
продуктов ради акции не добавляется. Сопоставление компонентов — точные ID и короткий
проверенный список альтернативных SKU фри, колы и чая с проверкой названия/объёма.
Неоднозначные совпадения по похожему названию не используются.

В `quote` дополнительно входят `original_total`, `savings`, `applied_deals`,
`items_price_basis="before_optimization"`, `optimization`. В каждом применённом
варианте — `kind` (`bundle`/`promotion`), `name`, `quantity` и исходные `items`,
которые он объединяет. `quote.items[].unit_price` — до оптимизации, `quote.total` —
итоговая подтверждённая цена. Сам набор и технические ID купонов не заменяют черновик.

`optimization` содержит `status` (`checked`, `partial`, `not_checked`),
`additional_quotes`, `reasons`, `globally_optimal=false`. Поиск ограничен 64
кандидатами, 24 локальными планами, пятью дополнительными расчётами и бюджетом около
70 секунд. Он выбирает лучший подтверждённый вариант из проверенных, без гарантии
глобального минимума. При отказе сервера или недоступности акций остаётся исходный
или уже подтверждённый более дешёвый вариант. Если выгодные варианты проверены
не полностью, результат содержит предупреждение.

Обычные акции читаются для каталожного ID ресторана и `channel_type=20`.
Учитываются активность, срок, канал, требования, минимальная сумма и лимит акций
из конфигурации. Дополнительно расчёт подтверждает совместимость и полный состав
`spPrices`: идентификаторы купонов, товары, количества, ошибки и сумму. Разные акции
могут сочетаться с наборами; отказ сочетания не заставляет повторять оформление.
Бонусные награды, промокоды, подписки, акции с неподдержанной персональной фильтрацией
или условиями не применяются. Списание бонусов остаётся нулевым.

`prepare_checkout` возвращает `original_total`, `savings`, `applied_deals`,
`optimization` вместе с итогом. Создание использует ровно проверенные `products` и
`spProducts`; повторная проверка акции и компонентов при той же сумме также может
инвалидировать подготовку. Скидка не означает готовность заказа к выдаче.

## Одноразовая карта и заказ

`prepare_checkout` требует авторизацию, выбранный ресторан и непустую корзину.
Повторно рассчитывает её и читает способы оплаты, выбирая только `card` из
`payment_methods` с известным провайдером (`sber_direct`, `sber_legacy`, `yookassa`).
`bindings`, СБП и SberPay игнорируются, даже если отмечены как способ по умолчанию.
Email для чека — строка до 200 символов; рассылка и сохранение карты передаются как
false. Бонусы не списываются. Телефон из входа вместо email не используется.

Для `parking` нужны все три поля: `parking_zone` — целое в диапазоне ресторана;
`vehicle_plate` — обычный российский госномер без пробелов (А123ВС77 или А123ВС777,
допустимы латинские эквиваленты букв); `vehicle_color` — `white`, `gray`, `black`,
`brown`, `beige`, `red`, `yellow`, `green`, `blue`, `purple`. Формат APK:
`carPlate: "<зона>-<три цифры><код цвета>"`. Для других способов поля запрещены.
Фактическую зону и машину определяет пользователь, не агент.

Подготовка возвращает `checkout_id`, `expires_at`, `total`, `currency`, `restaurant`,
`items`, `receipt_email`, `parking`, `payment_method:"card"`, `creates_order:false`.
Снимок привязан к эпохе входа, ресторану, способу и ревизии корзины, живёт 180 секунд.
`create_order` повторно проверяет полный состав с группами/компонентами, сумму и провайдера. Изменение или истечение
приводит к ошибке до запроса создания. Сервер может изменить сумму уже при создании:
результат содержит `quoted_total`, фактический `total`, `amount_changed`.
При отличии согласуйте новую сумму до передачи ссылки для оплаты.

Создание отправляется один раз, без повтора после 401 или транспортного сбоя.
Блокировка записывается до POST и не зависит от `request_id`, logout или 24-часового
срока результатов журнала. Один checkout нельзя использовать дважды. Повтор того же
request_id возвращает прежний снимок; для свежего состояния — `get_order_status`.
Новое оформление блокируется до терминального ответа по предыдущему известному ID.
Если ответ потерян без ID, автоматического восстановления нет: нужна проверка в
приложении/оператором. Не очищайте блокировку на основании таймаута. Проверка другого
ID не снимает её. При явно отклонённом создании нужна новая подготовка.

Заказ возвращает: `order_id`, `version_pos`, `status_code`, `status_name`, `total`,
`currency`, `payment_state`, `fulfillment_state`, `terminal`, `payment_url`,
`payment_method`, `pickup_number`, `payment_deadline`, `status_deadline`,
`can_cancel_order`, `failure_status_names`, `checked_at`, `suggested_poll_after_seconds`.
Создание дополнительно содержит `payment_link_available`, `quoted_total`, `amount_changed`.
Ссылка возвращается для нетерминального NEW/PAY_HOLD_IN_PROCESS/PAY_HOLD_ERROR,
если сервер дал HTTPS URL без userinfo и нестандартного порта. Отсутствие ссылки —
не повод создавать заказ заново. Скрипт никогда не посещает платёжный URL, не вызывает
возвратный URL и не передаёт туда токен аккаунта. В вывод не попадают PAN, invoiceId,
внутренние данные провайдера или сырой ответ заказа.

| `payment_state` | Интерпретация |
|---|---|
| `pending` | NEW / PAY_HOLD_IN_PROCESS; результата оплаты нет |
| `held` | PAY_HELD либо удержание в истории известных статусов исполнения |
| `captured` | PAY_COMPLETE либо списание в истории известных статусов исполнения |
| `error`, `timeout` | Ошибка платежа/списания/возврата или таймаут оплаты |
| `hold_release_pending`, `hold_release_error`, `hold_released` | Состояния освобождения удержания |
| `refunded`, `partially_refunded` | Возврат или частичный возврат по статусу сервера |
| `unknown` | Недостаточно данных, отмена без подтверждения возврата или неизвестный код |

Текущие ошибки/отмена/возврат имеют приоритет над историческим успехом.
`failure_status_names` сохраняет известные ошибки из истории заказа (например,
`FOE_VALIDATE_ERROR`) даже после `PAID_HOLD_CANCELLED`. Это диагностический код,
не доказательство конкретной причины. Отмена после освобождения удержания имеет
`fulfillment_state=cancelled`, `payment_state=hold_released`.
`fulfillment_state`: `preparing`, `ready_for_pickup`, `received`, `completed`,
`cancelled` либо `unknown`; оплата сама по себе не означает готовность еды.
`terminal` берётся из `statusDetails.isTerminal`, если он есть, иначе из известных
конечных кодов APK. Неизвестный код без флага не считается терминальным.
Сроки — ISO UTC из серверных epoch seconds либо null, без обещания 15 минут.
`version_pos` — служебное значение API. ID заказа — строка 1–128 латинских букв,
цифр, `_` и `-`; произвольные URL не принимаются. Последний ID сохраняется до чтения
остальных полей ответа: повреждённый ответ можно проверить отдельным GET.

Проверка статуса — один GET, без цикла/фоновой задачи. Рекомендованный интервал:
5 секунд для начальных состояний, 30 для остальных, null для терминальных.
Возврат из банка, текст «оплатил» и истечение срока не заменяют этот GET.

## Ошибки и восстановление

- `RESTAURANT_REQUIRED`: найдите и выберите точку. `RESTAURANT_NOT_FOUND`:
  обновите поиск; закрытые и удалённые точки не выбираются.
- `PICKUP_UNAVAILABLE`: выберите подходящую точку или согласуйте иной способ.
  Физическое Авто не означает мобильную выдачу на Авто.
- `PRODUCT_CONFIGURATION_UNSUPPORTED`: стандартные компоненты нельзя надёжно
  восстановить; выберите отдельный продукт без этой сложности.
- `PRODUCT_UNAVAILABLE`: черновик сохраняется; объясните отсутствующие ID и найдите
  замену. `CART_EMPTY`: сначала заполните черновик.
- `AUTH_REQUIRED`, `AUTH_EXPIRED`, `reauth_required`: восстановите вход.
  Статусы: `unauthenticated`, `pending_sms`, `authenticated`, `reauth_required`.
- `AUTH_SESSION_EXPIRED`: новая попытка входа по запросу пользователя.
  `ALREADY_AUTHENTICATED`: используйте сессию либо явно разрешённый logout.
- `RATE_LIMITED`, `BUSY`: соблюдайте `retry_after_seconds`.
- `ACCESS_DENIED` (403), `REQUEST_REJECTED` (другой неуспешный ответ): причина
  не угадывается. Details содержат фиксированный шаг, HTTP-код и JSON/non-JSON;
  код СМС не объявляется неправильным только по неизвестному ответу.
  Для JSON-ошибок `details.provider_errors`, если есть, содержит ограниченный список
  `{field,message}` с удалёнными секретами. Сообщайте конкретную причину отказа,
  не выдавайте 400 за сетевую блокировку и не меняйте способ оплаты наугад.
- `UPSTREAM_UNAVAILABLE`: GET исчерпал ограниченные повторы либо не удался расчёт.
  Расчёт можно повторить: этот POST не создаёт заказ. POST входа и refresh не повторяются.
- `OPERATION_OUTCOME_UNKNOWN`, `UPSTREAM_PROTOCOL_ERROR` на входе: не переотправляйте
  тот же шаг. Проверьте статус; для неопределённого refresh нужен явный локальный
  logout и новый вход. Токен, который мог быть заменён сервером, не переиспользуется.
- `REQUEST_ID_CONFLICT`: ID принадлежит другим аргументам или эпохе входа.
  `REQUEST_ID_EXPIRED`: старый ID не отправляется повторно. Повтор успешной локальной
  операции возвращает прежний снимок; актуальный черновик читается через `get_cart`.
- `QUOTE_NOT_CONFIRMED`: полный состав не принят сервером, заказ не создан.
- `CHECKOUT_EXPIRED`, `CHECKOUT_CHANGED`: новая подготовка и согласование результата.
- `CARD_PAYMENT_UNAVAILABLE`: карта не предложена; не заменять сохранённой/СБП.
- `PARKING_DETAILS_REQUIRED`, `CHECKOUT_PICKUP_UNSUPPORTED`: уточнить данные или способ.
- `ORDER_REQUIRED`: нужен ID заказа. `ORDER_IN_PROGRESS`: проверить предыдущий заказ.
- `OPERATION_OUTCOME_UNKNOWN`, `UPSTREAM_PROTOCOL_ERROR` после создания: не повторять
  POST; если известен ID, проверить статус, иначе нужна ручная проверка.
- `STORAGE_UNAVAILABLE`, `INTERNAL_ERROR`: не объявляйте успех.
- `PROXY_CONFIGURATION_ERROR`: оператору нужно исправить приватную настройку
  сети скилла; не читайте и не выводите её из хранилища в чат.

Состояние общее для чатов пользователя и защищено межпроцессным lock. ID операций
содержат HMAC-отпечатки аргументов, без номера и кода в журнале. Результаты хранятся
24 часа, блокирующие записи старых ID остаются. Локальная попытка входа живёт 10 минут;
до 5 проверок кода, не чаще одного начала входа за 60 секунд и трёх за 15 минут.
Это локальные ограничения. `expirationTime` провайдера не используется как доказанный
срок действия кода. Повторная отправка в той же попытке не реализована.

Access token обновляется при известном JWT exp менее чем через 300 секунд,
после 401 или JSON 403 с точным `detail: "Доступ истёк"`, с одной повторной
попыткой запроса, кроме создания заказа. Остальные 403 остаются ACCESS_DENIED.
Refresh передаёт
`refresh_token` и Bearer access token. При неизвестном результате ротации запрос
блокируется; сведения об expiry — подсказка, не доказательство авторизации.

Города кэшируются до часа, рестораны до 5 минут, продукты до 15 минут. Цены ресторана
читаются заново, перед расчётом обновляются рестораны. Меню/часы/пометки day_parts —
предварительные данные; расчёт подтверждает конкретный состав, но не резервирует его.
