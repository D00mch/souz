    steps:
      - id: credential

        args: ["${credential}"]
    returns: "${stored}"

# Ring Health — данные умного кольца Life Balance

Получай показатели владельца кольца для ответа на его запрос. Перед персональной оценкой используй релевантные данные; общие объяснения терминов не требуют обращения к API. При признаках возможной неотложной ситуации не откладывай рекомендацию обратиться за медицинской помощью ради запроса показателей.

## Вызов

Вызывай `RunSkillCommand`:
- `skillId` — id этого скилла из контекста активации;
- `runtime = BASH`;
- `scriptPath = scripts/ring.sh`;
- `args = [type, pageSize, page]` для отдельных показателей, последние два аргумента опциональны;
- `args = ["summary", "--timezone", "<IANA timezone>"]` для общей сводки;
- `args = ["full", "--days", "<1–7>", "--timezone", "<IANA timezone>"]` для разбора нескольких дней;
- `timeoutMillis = 20000` для отдельных показателей, `60000` для сводки или разбора периода.

Передавай `scriptPath` и `args`, не копируй скрипт в параметр `script`. Скрипт использует `curl`, `python3` и настроенный файл авторизации; не показывай учётные данные пользователю.

## Подключение кольца

При просьбе подключить кольцо или заменить токен вызывай только композит:
`RunSkillCommand` с `skillId = ring-health`, `arguments = {"composite":"connect","timeoutMillis":90000}`. Входных параметров нет. При отсутствии токена (`AUTH_REQUIRED`) во время запроса данных сразу вызови этот же композит: первоначальный запрос пользователя на данные разрешает предложить подключение через интерфейс клиента.

Композит детерминированно вызывает клиентский инструмент `ring.request_token` и передаёт его JSON-ответ скрипту сохранения. Клиент показывает поле ввода или берёт токен из своего хранилища; успешный ответ имеет вид `{"token":"<личный токен>"}`. Модель получает только итог сохранения. Не вызывай `ring.request_token` отдельно, не проси токен текстом в чате и не передавай его в параметры `RunSkillCommand`, память или заметки. Если пользователь уже прислал токен текстом, не повторяй и не используй его: предложи подключение через поле клиента.

У нового пользователя токена нет. Скрипт хранит его вне пакета, в `../.ring-health-state/token` относительно каталога `ring-health`, с правами `0600`, каталог — `0700`. Путь определяется и для `ring-health/bundles/<hash>`. Не используй `.lifebalance-auth`, общий токен или токен другого пользователя. `args = ["auth-status"]` у `scripts/ring.sh` проверяет только наличие, не возвращая значения.

Результаты композита:
- `ok = true`, `action = installed`: «Кольцо подключено».
- `action = updated`: «Токен обновлён».
- `action = unchanged`: «Этот токен уже сохранён»; повторная запись и проверка API не выполнялись, не утверждай, что доступ только что проверен.
- `ok = false`: объясни безопасную причину из результата. При `previousTokenPreserved = true` явно скажи, что прежний токен сохранён. Неверный формат и неуспешная проверка нового токена не меняют файл.
- `TOKEN_REQUEST_CANCELLED`: ввод отменён, не запрашивай токен снова в этом ответе.
- `TOKEN_REQUEST_FAILED` или `TOKEN_REQUEST_TIMEOUT`: не удалось получить токен от клиента; не предлагай прислать его текстом.
- Если `ring.request_token` недоступен в каталоге чата, объясни, что этот клиент не поддерживает подключение кольца; не обходи это чтением файлов или вводом токена через LLM.

Не более одного вызова `connect` за ответ. После успешного подключения, если исходный запрос был о показателях, повтори нужный запрос данных один раз и ответь на него. После неудачи или отмены остановись. Отвечай коротко, без путей файлов, имён полей JSON и технических операций, если пользователь их не просил.

## Ошибки API

Одиночные запросы и `summary`/`full` возвращают безопасную ошибку `error` с `code`, `httpStatus`, `message`, `retryable`; код завершения ненулевой. Сводка сохраняет уже полученные метрики, помечает `ok = false`, `partial` и прекращает дальнейшие запросы после HTTP-ошибки. Это ошибка запроса, а не подтверждение отсутствия измерений. Не перезапускай сводку или ту же команду автоматически.

- `401 / AUTH_INVALID`: API не принял токен. Для восстановления доступа вызови `connect` один раз, если в этом ответе он ещё не выполнялся; после отказа проверки нового токена повторно не вызывай. Не утверждай без оснований, что он истёк. Сохранённый файл автоматически не удаляется.
- `403 / ACCESS_DENIED`: доступ запрещён. Предложи проверить права токена и доступ к данным кольца; пользователь может попросить переподключение через `connect`. Не называй это доказательством истечения токена.
- `400 / BAD_REQUEST`, `422 / INVALID_REQUEST`: API отклонил запрос или его параметры. Сообщи о неудаче запроса; не проси повторную авторизацию только на основании этого статуса и не удаляй токен.
- `404 / NOT_FOUND`: ресурс API не найден; это не означает, что измерений нет.
- `408 / REQUEST_TIMEOUT`, `429 / RATE_LIMITED`: предложи повторить позже. Не повторяй запросы в этом же ответе и не проси новый токен.
- Другие `4xx / CLIENT_ERROR`: назови статус и сообщи, что API отклонил запрос, без выдуманной причины и без автоматического повтора.
- `5xx / SERVICE_UNAVAILABLE` и `NETWORK_ERROR`: временная недоступность; предложи повторить позже, не меняя токен.

При ошибке проверки нового токена объясни причину по этим же правилам и явно скажи, что замена не выполнена. Не показывай тело ответа API или значение токена. Ненулевой код не позволяет заявлять об успешной установке или об отсутствии данных; уже полученную часть сводки используй только с оговоркой об ошибке и неполноте.

## Когда обращаться к кольцу

Выбирай минимальный запрос, который поможет ответить. Вопрос о длительности сна требует данных сна, а не всех показателей. Общая оценка восстановления может потребовать нескольких метрик: используй `summary`. Для разбора нескольких дней используй `full`.

Если в текущем диалоге уже есть данные с понятными источником, датами и достаточным охватом, используй их повторно. Для вопроса «сейчас» проверь свежесть. Сводку, переданную приложением, отличай от ответа API. При расхождении не смешивай их молча: назови источник, время и различие, не объявляй один источник правильным без основания.

Жалоба сама по себе не означает, что кольцо способно объяснить её причину. Не делай запрос кольца условием сочувствия, общего объяснения или обращения за помощью. Уточняй самочувствие только если это повлияет на ответ; не повторяй уже отвеченный вопрос.

## Сводка и разбор периода

Сводки возвращают JSON; расчёты выполняются скриптом. Часовой пояс берётся из контекста пользователя и передаётся явно; если его нет и он влияет на границы суток, уточни. Для отдельной записи без дневного сравнения можно использовать обычный запрос метрики.

- `summary`: сессии сна за последние 7 суток по времени начала; пульс, стресс, HRV, SpO2 и температура за последние 3 часа; шаги с начала текущего дня. Последняя доступная запись каждой метрики показана отдельно, даже если она старше окна.
- `full --days N`: от полуночи первого дня до текущего момента, с группировкой в часовом поясе пользователя. По умолчанию 3 дня, максимум 7. Сессии сна выбираются по времени начала; это не гарантирует все сны, закончившиеся в периоде. Для запроса по времени пробуждения запроси дополнительную историю и явно обозначь ограничение доступных полей.
- `generatedAt`, `from`, `to`, `latestAgeMinutes`: время формирования, фактическое окно расчёта и возраст последней записи. `latest` — не обязательно «сейчас». Время замера не доказывает время синхронизации.
- `recordCount`, `count`, `missingCount`: количество записей и заполненность каждого поля. `null` остаётся отсутствием; отсутствие записей шагов не превращается в нулевую активность. Средние рассчитаны по доступным замерам, без взвешивания по времени.
- `coverage.historyTraversalComplete`: удалось пройти историю до границы окна или конца выдачи. Даже `true` не подтверждает непрерывность измерений. `warnings` указывает на исключённые будущие/неоднозначные даты, повторения и нарушение порядка.
- `coverage.stopReason`: `time_budget`, `page_limit`, `pagination_stalled`, `api_error`, `invalid_response` и коды HTTP-ошибок в нижнем регистре означают неполную выгрузку. При HTTP-ошибке `coverage.error` и верхнеуровневый `error` содержат её причину; уже полученные метрики сохраняются, дальнейшие не запрашиваются. При частичном ответе оговори ограничение; не называй полученную сумму полным итогом дня. Если конкретная метрика не получена, не подменяй её старым значением.

Одна команда ограничена 50 секундами, каждый показатель — 15 страницами по 100 записей. При неполном охвате можно запросить нужный показатель отдельно; не повторяй автоматически всю сводку. Скрипт не вычисляет диагнозы, «Ресурс», категории стресса, признаки снятого кольца или неподтверждённые фазы сна. Агрегаты `ntc` и `bosh` представлены отдельно в °C; исходные поля в `latest` остаются в тысячных долях °C.

## Данные

| `type` | Поля и ограничения |
|---|---|
| `sleep` | Сессии сна: `startTime`, `calculatedStartTime`, `date`, `totalSleepTime` (минуты), `sleepScore` (0–100), `minHeartRate`, `avgHrv`, `avgSpo2`, `sleepId`, `source`. Оценка и средние показатели могут быть `null`. Одна сессия не обязательно равна одной ночи. |
| `heartrate` | `heartRate` (уд/мин), `date`. |
| `hrv` | `hrv`, `date`. API не сообщает метод расчёта и единицы; не придумывай их и универсальную норму ВСР. |
| `stress` | `stress` (шкала 0–100), `date`. Число само по себе не раскрывает причину стресса; границы низкого/высокого уровня не заданы. |
| `step` | `step`, `distance` (метры), `calories`, `date` — записи активности за интервалы. |
| `spo2` | `spo2` (%), `date`. |
| `temperature` | `ntc`, `bosh`, `date`. Значения температуры кожи в тысячных долях °C: дели на 1000. Это не измерение внутренней температуры тела. |

`null` или отсутствующее поле означает отсутствие данных, а не ноль. Нулевое значение не заменяй пропуском без основания. Не выводи больше точности, чем дают измерения.

Строка `sleepQuality` содержит кодировку фаз по интервалам и удаляется скриптом: схема её расшифровки не предоставлена. Не вычисляй длительности фаз из оставшихся полей. Отдельного запроса или документированного поля «Ресурс» нет; не рассчитывай его самостоятельно. `source` — метка источника записи, а не оценка качества измерения.

## История, время и полнота

Ответ содержит `content` и пагинацию: `currentPage`, `pageSize`, `totalElements`, `totalPages`, `isFirst`, `isLast`. `totalElements` — число записей, не дней. `pageSize` — от 1 до 100, по умолчанию 7 для сна и 30 для остальных типов. `page` начинается с 0; первые страницы содержат более свежие записи.

Количество записей **не задаёт длительность периода**: частота различается по метрикам, возможны пропуски. Проверяй реальные `date`/`startTime` с их часовым смещением. При сравнении с «сейчас» используй текущее время из контекста/доступного инструмента, а не время последней записи. У разных метрик могут быть разные последние даты. Свежесть ограничена синхронизацией с телефоном; API не даёт отдельного подтверждения последней синхронизации или качества записи.

Для нужного периода:
1. Запроси страницу 0 и проверь временной охват. Если нужен более ранний участок, увеличивай `page`, сохраняя тот же `pageSize`.
2. Остановись, когда достигнута нижняя граница периода, `isLast = true` или `content` пуст. Не выгружай всю историю без необходимости. Если следующая страница повторяется или не даёт более ранних записей, прекрати и сообщи об ограничении.
3. Отбирай записи по датам нужного периода, учитывая часовой пояс пользователя. Если он неизвестен и влияет на границу дня, уточни его. Не суммируй записи повторно при перекрытии страниц; если не удаётся однозначно отличить дубликаты, укажи неопределённость.

Параметры `from/to` в команду не передаются: запросы API с фильтром дат могут зависать. Для истории используй страницы.

Достижение границы периода подтверждает только охват выгрузки, а не непрерывное ношение кольца или полноту измерений. Описывай шаги как «по доступным записям за … до …». Не называй сумму последних 100 записей итогом суток. Сравнивай одинаковые периоды и учитывай незавершённый текущий день.

## Выбор запроса и ответ

- «Как я спал?» → `["sleep"]`. Укажи нужную сессию и длительность в часах и минутах, используй только заполненные показатели. Сравнивай с явно названными сессиями/периодом; 7 записей не обязательно охватывают неделю.
- «Как моё состояние?» / «Стоит ли тренироваться?» → `["summary", "--timezone", "<часовой пояс пользователя>"]`. Ответ опирается на релевантные метрики и фактическое самочувствие; сводка сама по себе не определяет готовность к нагрузке.
- «Сколько шагов сегодня?» → `["step", "100"]`, затем при необходимости `["step", "100", "1"]` и далее до границы дня. Отфильтруй записи другого дня перед суммированием шагов и дистанции.
- Динамика ВСР → `["hrv", "100"]` либо `avgHrv` в сессиях сна. Не смешивай отдельные измерения и среднее за сон в одном сравнении. Для истории сна можно запросить `["sleep", "30"]` и дополнительные страницы.

Отделяй наблюдение от гипотезы: «ниже, чем в предыдущих трёх сессиях» не означает «ниже нормы» или установленную причину. Короткая выборка не задаёт личную норму; одинаковое число записей не делает периоды сопоставимыми. Не называй изменение устойчивым без достаточной сопоставимой истории. Привычное значение не гарантирует здоровье, хорошие показатели не опровергают жалобы человека.

Не ставь диагнозы и не назначай лечение по кольцу. При сохраняющихся жалобах или беспокоящих симптомах рекомендуй медицинскую консультацию без постановки диагноза. Не повторяй медицинский дисклеймер в каждом обычном ответе. Дай главный вывод и релевантное основание; для голосового канала обычно достаточно 2–4 фраз без таблицы.

Если команда завершилась с ненулевым кодом или `Error:`, сообщи о недоступности данных, не выдумывая значения и причину сбоя. Обрабатывай причину по разделу «Ошибки API»; при `401` используй правила раздела «Подключение кольца». При отсутствии данных можно объяснить общий принцип, явно отделив его от персональной оценки; не проси выгрузку с кольца и не обещай исправлений, которые не выполняешь.

## Продуктовая справка и поиск врача

Для настройки, синхронизации, возможностей кольца и значения метрик приложения используй `ring-help`, если он доступен. Передавай общий вопрос о продукте без личных показателей и симптомов. Описание метрики в справке не подтверждает её наличие или кодировку в API.

При сохраняющейся жалобе или необходимости медицинской консультации можно предложить поиск врача через `doctor-appointment`, если этот скилл доступен. Переходи к поиску после согласия; уже полученное согласие не переспрашивай. Не запускай запись автоматически и не обещай доступные слоты до результата поиска. Если скилла нет, не обещай поиск. Хорошие показатели кольца не отменяют жалоб, а числовые пороги без подтверждённого основания не выбирают специальность врача. При срочной ситуации не задерживай обращение за помощью ради кольца или записи.
